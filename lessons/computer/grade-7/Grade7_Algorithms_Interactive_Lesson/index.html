🧠 CORE CONCEPTS

Build the mental model

Algorithm = the plan

A logical, ordered procedure that describes how to solve a problem. It can be written in natural language, a flowchart, or another representation.

Think: A recipe is a plan. It tells you what to do and in what order.

Pseudocode = the draft

A simplified, human-readable description of program logic. It resembles programming structures but does not follow the exact syntax of one programming language and cannot normally be executed directly.

Think: Pseudocode is the rough blueprint you prepare before writing real code.

Program = the working code

An implementation written using the rules and syntax of a programming language so a computer can process it with the appropriate compiler or interpreter.

Think: The blueprint becomes the actual building.

🧩 BUILDING BLOCKS

The 3 structures of an algorithm

Most algorithms combine these three ideas.

01

Sequencing

Steps are performed in a specific order, normally once.

Example: Convert pounds to kilograms
  1. Read the weight in pounds.
  2. Divide pounds by 2.2046.
  3. Display the kilogram value.
02

Selection

A condition determines which action happens.

Example: Compare two numbers
IF A > B THEN
  display A
ELSE
  display B
03

Iteration

A set of steps is repeated a number of times or until a condition is met.

Example: Practice a difficult music section
  1. Practice the section.
  2. Check for mistakes.
  3. Repeat until accurate.

⌨️ PSEUDOCODE LAB

From idea → pseudocode → program

Linear Search

Suppose the list is [7, 2, 9, 4, 6] and the target is 4. A linear search checks items one by one from the beginning until it finds the target.

PSEUDOCODE 
FUNCTION linearSearch(list, target)
  FOR each item from first to last
    IF item == target THEN
      RETURN position
    ENDIF
  ENDLOOP
  RETURN -1
END FUNCTION

How to read it

FUNCTIONnames the task
FORrepeats through items
IFchecks a condition
RETURNgives the result

✅ QUALITY CHECK

What makes an algorithm good?

Input-specified

Clearly identifies the information the algorithm accepts.

Output-specified

Produces at least one well-defined result.

Clear & unambiguous

Each step has one clear meaning.

Feasible

Can actually be carried out using available resources.

Language-independent

The logic is not tied to one programming language.

Finite

Stops after a limited number of steps/time.

Effective

Uses basic, practical operations that can be followed or traced.

Deterministic

For the same input, it should give the same expected result when deterministic behavior is intended.
